# 任务看板接入与迁移

## 当前实现

- 看板页头显示现有正式队标与“燕山大学燕鹰战队”，桌面三栏、手机换行；首次进入成功回到页顶，自动刷新保留滚动位置。
- 页面地址 `/dashboard`，实验室大屏可使用 `/dashboard?screen=1`，导航中的“看板”也可进入。
- 看板使用独立的深蓝科技风：网格背景、霓虹面板、数字仪表与真实数据比例条；离开看板后恢复全站原有主题。系统启用“减少动态效果”时关闭扫描和呼吸动画。
- 网站继续使用 `npm run generate` 静态生成；任务在浏览器中请求 `/api/dashboard`，不在构建时读取飞书，不生成任务 JSON 快照。
- EO 入口为 `edge-functions/api/dashboard.js`，使用 Web API 和 JavaScript，不需要 PHP、独立服务器或新数据库。接口仅接受 GET；获取飞书访问令牌时使用认证 POST，不新增、修改或删除任务。
- 赛事倒计时在 `app/data/competitions.ts` 集中维护，当前预留2027 RMUL山东站和2027 RMUC，均显示日期待定；维护步骤见[赛事倒计时配置](赛事倒计时配置.md)。更改配置后随Git构建部署生效，与飞书任务刷新独立。
- 任务列表、状态、组别与关键词筛选、最近截止倒计时、待办/已完成个人任务榜均已实现。大屏每 15 秒轮播任务分页，可暂停；GitHub 动态为可选项。
- 任务区通过 ResizeObserver 测量实际宽高，以16px人员字号时360×260px卡片为基准，随实际字号等比放大最小尺寸，并结合间距计算列数、行数和每页容量；调整窗口、切换大屏时重新计算，不固定为6项。固定大屏利用剩余高度，长内容可在卡片内滚动，个人榜显示前4名；只有满足桌面大屏尺寸（宽至少1200px、高至少700px）且已开启大屏时分页；普通模式、手机和平板完整显示当前筛选结果，单列或自适应列数向下滚动，不显示翻页和轮播按钮。GitHub 动态每20秒切换一组。
- 看板人员字号为16–20px、头像30–42px，随视口适度增大；标题约18–23px，备注、时间、标签和排行榜同步放大。大屏分页按当前实际字号重算容量。
- 执行人、发布人和任务榜中的头像、姓名匹配内容仓库已有成员姓名后，链接至 `/team/姓名`，并可使用已有成员头像；没有成员档案时仅展示，不提供点击入口，也不会新建空档案。新增成员资料后重新构建即可参与匹配。
- 正常每 30 秒读取一次接口，页面隐藏时暂停请求，返回页面时刷新。状态按当前时间重新判断，未完成任务到期后自动进入逾期列表。
- **缺少配置时只显示“看板尚未开放”，不会用模拟任务填充线上页面。**逐步配置与真实联调进度见 [飞书看板配置实录](飞书看板配置实录.md)。

## 一、准备飞书表格

建议字段如下；字段名可按下一节映射：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| 任务名称 | 文本 | 有内容的任务必填，空白行忽略 |
| 所属组别 | 单选或多选 | 按实际表格标签显示；多选标签分别筛选，不合并成一个标签 |
| 执行人 | 人员 | 支持多人；为空时显示待分配 |
| 发布人 | 创建人或人员 | 自动记录发布者；不要使用邮箱代替姓名 |
| 截止时间 | 日期时间 | 建议显示时分；网站统一按北京时间展示 |
| 优先级 | 单选 | 高、中、低；也兼容文章中的 P0-高、P1-中、P2-低 |
| 完成状态 | 单选 | 未完成、已完成，默认未完成 |
| 完成时间 | 日期时间 | 飞书自动化在完成时填写，用于已完成列表排序 |
| 备注 | 文本 | 可选 |

默认兼容文章的“最晚截止日期”“完成情况”字段名。其他状态（如已取消、进行中）需先明确对应规则再调整代码；接口会报告字段错误，不把未知状态当作未完成。

创建表单视图供成员发布任务；完成按钮、发布群通知/私信、完成通知、每日未完成提醒均在飞书自动化中配置，不依赖网站是否打开。多人任务的执行人各计一次，榜单数量不等于去重任务总数；待办榜包含逾期未完成任务。人员按飞书返回的标识去重，同名不同人不合并。

创建飞书自建应用，开通多维表格记录读取所需权限，发布应用，并授予这张表的读取权限。**不要为这个只读看板额外授予任务写入权限。**需要提醒时按飞书流程开启机器人能力和发送消息所需权限。当前接口不额外查询通讯录：使用表格返回的姓名、头像；可匹配官网已有成员头像，仍没有头像时显示姓名首字。

官方参考：[列出记录](https://open.feishu.cn/document/server-docs/docs/bitable-v1/app-table-record/list)、[自建应用获取 tenant_access_token](https://open.feishu.cn/document/server-docs/authentication-management/access-token/tenant_access_token_internal)。

## 二、EO 运行时环境变量

在 EO 项目的环境变量中配置；密钥不用发到聊天、不提交 GitHub，不加 `NUXT_PUBLIC_` 前缀。变量需要提供给函数运行时，不能只存在 GitHub Actions 构建环境里。

| 变量 | 用途 |
| --- | --- |
| `DASHBOARD_ENABLED` | 准备好后设置 `true`，默认关闭 |
| `DASHBOARD_PUBLIC` | 默认 `false`，仅明确允许所有访客读取任务时才设置 `true` |
| `DASHBOARD_ACCESS_CODE` | 非公开看板必填，12–128 位随机英文、数字或 ASCII 符号，不含空格；浏览器每次请求校验 |
| `FEISHU_APP_ID` | 飞书自建应用 App ID |
| `FEISHU_APP_SECRET` | 飞书自建应用 App Secret |
| `FEISHU_BITABLE_APP_TOKEN` | **实际多维表格** app_token，通常来自 `/base/` 地址；不是 tenant_access_token |
| `FEISHU_BITABLE_TABLE_ID` | 表格 ID，通常为 `tbl...`，不是视图 ID |
| `FEISHU_BITABLE_VIEW_ID` | 可选，仅读取指定视图；所有统计仅针对实际返回的记录 |
| `FEISHU_FIELD_MAP` | 可选，JSON 字段名映射 |
| `DASHBOARD_GITHUB_REPOS` | 可选，最多 5 个公开仓库，格式 `owner/repo,owner/another` |
| `DASHBOARD_GITHUB_TOKEN` | 可选，仅用来提高 GitHub API 限额，使用最小读取权限 |

如果使用飞书 `/wiki/` 地址，不能直接把知识库节点 token 当作多维表格 app_token。先通过飞书开放平台查询节点信息，取得实际表格的 `obj_token`，同时确认 `obj_type` 是 `bitable`。不清楚时先提供普通表格链接确认，避免复制错 token。

例如实际列名为“名称”“状态”“负责人”，可填写：

```json
{"title":"名称","status":"状态","assignees":"负责人"}
```

映射键完整列表为 `title`、`group`、`assignees`、`publisher`、`deadline`、`priority`、`status`、`completedAt`、`note`。只写需要替换的项，其他字段沿用默认名称。

没有设置 `DASHBOARD_GITHUB_REPOS` 时不显示研发动态，不自动推断团队组织或仓库。GitHub 贡献榜汇总每个已配置公开仓库前 100 位贡献者的 API 贡献数，不代表团队所有仓库的完整贡献总数；最近动态显示 GitHub 公共事件，有 API 自身的延迟。

配置完环境变量后按 EO 要求重新部署函数，验证 `/api/dashboard` 已路由到函数而非静态 404。函数按平台规则独立于 Nuxt 静态产物部署，不要在 `public/api/dashboard` 放静态数据，否则可能覆盖函数路由。官方参考：[Edge Functions](https://pages.edgeone.ai/zh/document/edge-functions)。

## 三、访问和缓存

- 未开放返回 503；需要口令返回 401；成功返回 200；暂时读不到数据返回 502；非 GET 返回 405。
- 502 的 `reason` 提供固定诊断代码，例如 `FEISHU_AUTH_FAILED`（应用认证失败）、`FEISHU_READ_FAILED`（表格权限、标识或读取异常）、`INVALID_TASK_STATUS`（完成状态不符合约定）、`INVALID_FIELD_MAP`（字段名映射异常）、`TASK_LIMIT_EXCEEDED`（记录超限）；不返回上游原始响应或凭证。
- 口令可由管理员自定：EO 项目设置 → 环境变量 → `DASHBOARD_ACCESS_CODE` → 编辑 → 填入至少12个字符的新值 → 确定 → 重新部署。口令变更由管理员亲自输入并保存；不要写入源码、日志或此文档。解锁入口在桌面采用双栏布局、手机采用单栏，窄屏输入框和按钮纵向排列。提交后立即显示加载动画，跟随真实口令验证及任务读取请求结束，成功后淡入看板、失败后恢复输入；没有人为延迟。
- 队内口令通过 HTTPS Authorization 请求头发送，仅保留在当前页面内存，不写 URL、浏览器存储或构建产物。刷新页面后需重新输入；点击“锁定”清除当前页面数据和口令。
- 共享口令提供整个队内看板的读取权限，不区分个人、不是飞书单点登录。需要按成员控制访问或撤销单个成员权限时再增加身份认证。EO 可配置访问频率限制；公开模式应仅包含允许公开的任务。
- API 响应标记 `no-store`，避免受保护的数据落入公开 CDN 缓存。函数内部只在运行实例内缓存任务 30 秒、复用未过期的飞书令牌，并合并并发读取；不同配置的缓存隔离。
- 这是可丢弃的临时内存缓存，不保证跨节点、实例冷启动后的全局命中率。没有任务数据库、没有本地缓存文件、没有必须迁移的 KV 数据。
- 飞书读取失败时，最多保留 15 分钟内的旧结果，并在页面显示更新时间和更新中断提示；超过期限接口报错，页面已有结果仍带中断提示保留，不能视为实时进度。
- 最多完整读取 2000 条记录，超过上限或分页异常返回错误，不会把不完整列表作为成功结果。任务多时可指定一个“本赛季任务”视图，或后续增加分页方案。
- GitHub 独立缓存：未配置令牌时 30 分钟，有令牌时 10 分钟。GitHub 故障不阻塞飞书任务，页面显示研发动态更新中断，至多保留一天内的 GitHub 旧结果。

## 四、本地预览与检查

```bash
npm run dashboard:test
npm run generate
npm run dashboard:preview
```

打开 `http://127.0.0.1:8790/dashboard/`，大屏使用 `/dashboard/?screen=1`。预览脚本只监听本机，读取已生成的静态页面，并由本地服务器提供演示数据；页面明确标记“本地演示数据”。示例位于 `tests/fixtures/dashboard.mjs`，不复制到内容仓库或 `public`，也不被生产函数引用。

`nuxt dev` 自身不模拟 EO 函数路由；不启用本地预览服务器时可能显示尚未开放。带真实凭证的联调应在 EO 函数环境进行，分别确认：多维表格读取权限、字段映射、表单新增、完成状态及完成时间更新、飞书自动化通知、页面刷新与权限保护。当前单元测试使用模拟上游，不能证明真实账号权限或 EO 线上网络已通过。

## 五、换 EO 账号

1. 新账号导入同一 GitHub 仓库，确认可用的 Functions 功能和额度。
2. 重新设置本节环境变量、部署函数与静态站，输入口令验证任务和动态。
3. 新建部署钩子，更新内容仓库的 `EO_DEPLOY_HOOK_URL` Secret。
4. 新项目验证成功后切换域名，按 EO 要求处理 DNS 与 SSL。

飞书组织、应用、表格和自动化不变就无需迁移任务数据。更换口令、表格或应用凭证时不复用旧配置缓存；新 EO 实例自动从飞书重新获取数据。不要将真实任务快照提交到公开 GitHub 仓库。
