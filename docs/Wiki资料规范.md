# Wiki frontmatter 规范

生效日期：2026-10-20。手写字段仅为 `title` 和 `authors`；教程首页与章节使用相同格式。

## 基本格式

```yaml
---
title: "路径规划器"
authors:
  - 董佳辉
---
```

`title` 必填，使用非空标题，不手动添加章节编号。`authors` 可选，使用姓名数组；一位或多位作者都采用列表格式。

```yaml
authors:
  - 董佳辉
  - 张三
```

不要写成 `authors: 董佳辉` 或把多人合并成一个姓名。姓名不能为空、只有空格或重复，不填写 `null`。作者无需有团队成员档案，在成员档案中有同名人员时，读取该档案的头像与姓名，点击进入对应成员详情；没有成员档案时使用站点默认头像，点击进入 `/authors/姓名` 作者页，展示姓名与其署名的教程及章节。作者页沿用首页继承、章节覆盖和显式空列表规则，不推测或编造个人资料。

## 首页继承与章节覆盖

- 教程首页 `index.md` 可填写整套教程的默认作者。
- 章节省略 `authors` 时，继承所属教程根目录 `index.md` 的作者；没有默认作者时不显示作者行。
- 章节明确填写 `authors` 时，覆盖默认作者，不与默认作者合并。
- 明确填写 `authors: []` 表示该页不展示作者，也不继承。
- 多层目录的章节同样继承整套教程根目录首页，不逐级推测作者。

网站在页面标题下显示“作者：”及各作者的头像、姓名；头像和姓名共用一个资料链接：已有成员档案时进入成员详情，否则进入作者页。多人作者分别展示，窄屏自动换行。显式空列表不显示作者栏。

## 自动生成的信息

目录名称与章节文件名继续决定页面路径、目录归属、章节顺序和编号。现有 `date` 从教程目录前缀提取，表示教程目录日期，不代表文章更新时间。

`path`、`date`、`chapterOrder`、`chapterDepth`、`docKey`、`docRoot`、`docTitle`、`isWikiDoc`、`isWikiIndex`、`wikiDepth` 由现有处理流程生成，不在手写 frontmatter 中填写。新增其他手写字段时，先更新规范和校验规则。

## 来源说明

作者用于署名，转载来源、参考资料和贡献说明继续写在正文中。作者字段本身不替代引用来源，也不自动生成版权或授权声明。

## 检查

网站仓库的 `utils/wiki-authors.mjs` 定义手写字段和作者继承规则。`npm run wiki:check` 检查 YAML、标题、作者格式、重复姓名、未知字段及原有章节/链接规则；正式构建前会自动运行。

`npm run wiki:test` 验证单人/多人作者、缺省继承、章节覆盖、显式空数组，以及空姓名、重复姓名等错误输入，并验证成员头像、详情地址、外部作者页入口，以及作者页文章列表的继承与覆盖。

Nuxt 静态生成完成后，在 Nitro `compiled` 生命周期检查本次构建的实际输出目录：本地通常是 `.output/public`，EO Nuxt 适配器会改为 `.edgeone/assets`。检查逐一确认源文档对应的 HTML 存在、非空且包含文章标题区域；缺失或空白时停止构建，不使用其他目录的旧产物回退。预渲染并发固定为 4，避免构建机器核心数量变化导致过多页面同时处理。

手动复查本地产物可运行 `npm run wiki:output-check`；检查 EO 目录时运行 `npm run wiki:output-check -- .edgeone/assets`。`npm run wiki:output-test` 验证两个目录以及缺失、空白页面和旧产物干扰的情况。
