# GitCode 研发动态接入

任务看板的“研发动态”只接入 GitCode，包含代码贡献榜、最近更新及各仓库同步状态。组织及逐仓库同步详情默认收起，点击“同步详情”展开；同步中断或部分结果提示仍直接显示在标题栏。飞书继续提供任务，两部分独立读取；无需新增数据库，也不需要修改飞书表格。

## 配置仓库

在 EO 项目中为函数运行时设置以下变量，保存后按 EO 要求重新部署。下面example-team相关仓库和账号为占位示例；当前实际目标为ysu_RM组织，真实令牌与生产联调状态以开发实录为准。

| 变量 | 用途 |
| --- | --- |
| `DASHBOARD_GITCODE_ORG` | 组织模式，填写`ysu_RM`或`https://gitcode.com/ysu_RM`；自动发现当前令牌可读取的全部代码仓库 |
| `DASHBOARD_GITCODE_EXCLUDE_REPOS` | 可选排除清单，英文逗号分隔的完整仓库路径或GitCode仓库地址；组织模式仅允许同组织项目 |
| `DASHBOARD_GITCODE_REPOS` | 未配置组织时才使用的手动模式，最多5个仓库，英文逗号分隔；组织模式优先，不与此列表相加 |
| `DASHBOARD_GITCODE_TOKEN` | 接口需要认证时填写有读取权限的个人访问令牌，仅放在EO函数运行时 |
| `DASHBOARD_GITCODE_PEOPLE` | 可选，JSON数组，将提交作者或账号对应到队员姓名 |

手动仓库及排除清单可填写简写或完整地址，也兼容末尾的 `.git` 和 `/`：

```text
example-team/robot,https://gitcode.com/example-team/documents
```

仅接受 `gitcode.com` 下的仓库，不接受组织首页、Issue页面、其它平台、带令牌参数或账号密码的地址。重复填写同一仓库只统计一次；同一项目存在不同镜像或Fork时，应只配置作为统计依据的那一份，不会跨仓库自动判断提交是否相同。

组织和手动仓库均未设置时整块隐藏。仅显式配置组织后才自动发现该组织仓库，不扫描账号的其它组织或个人仓库。配置错误时显示“仓库配置待检查”，飞书任务继续正常展示。原来的 `DASHBOARD_GITHUB_REPOS` 与 `DASHBOARD_GITHUB_TOKEN` 不再读取，可从EO删除；仅保留旧页面响应字段兼容，不再访问GitHub接口。

GitCode令牌由管理员直接填写到EO，不发到聊天、不提交仓库、不使用 `NUXT_PUBLIC_` 前缀。函数只请求组织项目目录（组织模式）、纳入仓库的贡献者和动态，不读取源码、不执行写入。令牌能够读取的私有仓库，其作者统计和动态会展示给能够访问当前看板的人，应按实际看板受众选择仓库和令牌权限。

### 经典令牌权限核对

2026-10-23在本机Chrome实际查看个人设置“访问令牌（经典）→新建访问令牌”：表单默认14项均为读写，不能直接沿用默认授权。原单仓库方案为“项目”只读、其它13项禁止。组织模式的待验证方案改为“组织”和“项目”只读，其余12项禁止（用户、Key、组织看板、组织讨论、企业、PR、Issue、Notes、Hook、Repository、Action、项目讨论）。这里的Repository说明为bash客户端上传下载，看板使用贡献者和仓库动态API，不执行Git克隆或推送。

2026-10-23已在本项目EO生产函数环境持真实令牌验证：组织目录11仓、11仓贡献和动态均读取成功，未扩大为全读写。不同账号的实际可见范围仍须分别核对；若出现权限拒绝，按具体接口检查，不能据此承诺任意令牌都可解决403。名称、有效期、生成及EO保存由用户亲自完成，密钥未经过聊天或仓库；无需把通知机器人密钥当作GitCode令牌。

## 整个组织的读取方式

当前建议配置：`DASHBOARD_GITCODE_ORG=ysu_RM`，排除清单先不填。旧的单仓库变量可移除；保留时会被组织模式忽略，不限制为一个或五个仓库。

- 按`type=all&repo_type=code&per_page=100`逐页读取官方组织项目列表，涵盖令牌可见的公开、私有代码仓及归档代码仓，不读取模型、数据集、Space。网页登录账号的可见范围与令牌权限不一定相同，必须实际核对。
- 每次目录更新先获取完整分页，再替换上次目录。重复页、错误响应、跨组织路径或后续页失败均明确标记列表更新中断，不把首100项或旧手动配置当成完整组织。超过100页（10000项）的保护上限也会明确失败，不静默截断。
- 目录与各仓库的贡献、动态独立缓存；有令牌10分钟、无令牌30分钟。新仓库在目录缓存到期后自动纳入，离开组织的仓库从新目录移除。失败后退避60秒，最长一天回退旧目录并保留真实更新时间。
- 每次请求最多等待GitCode同步8秒，最多4个上游请求同时运行；未轮到的仓库及缓存到期但尚未刷新的项显示等待同步，后续轮询按游标继续。慢请求会被取消，飞书任务不因GitCode超时报错；首次进入仍可能等待这段同步预算。
- 页面显示当前组织、已同步/纳入数量、目录更新时间和逐仓库状态。部分同步期间明确提示“当前为部分结果”，不会把未读取仓库记作零贡献；仓库状态列表可滚动查看全部项。
- 同一路径或同一项目ID去重。Fork会标识但默认仍纳入，不因为名称或Fork身份擅自丢弃。不同镜像之间的相同提交不会自动按SHA去重；确认重复后用`DASHBOARD_GITCODE_EXCLUDE_REPOS`排除指定副本。例如`example-team/robot-mirror,example-team/archived-copy`。排除清单里的归档例子仅是配置示例，归档仓库本身不会自动排除。
- 当前用户要求读取所有仓库，因此不预先排除训练仓、文档仓、旧赛季仓或名称相近的项目。今后调整排除清单后重新部署；全部排除会明确显示当前没有纳入仓库。

## 对应人员、头像及个人页

日常对应以内容仓库成员资料中的 `links.gitcode` 为准，无需在 EO 再维护人员表：

```yaml
links:
  gitcode: https://gitcode.com/example-member
```

页面读取已生成的成员链接，优先按接口确认的公开账号匹配；作者接口只有 Git 作者名时，仅尝试与已填写账号精确匹配（不区分大小写），不会把任意作者名拼成陌生人的个人主页。一个账号对应多份档案时不擅自选人。匹配后使用该档案的姓名、照片及 `/team/姓名` 入口；未匹配保留 GitCode 名称，使用圆形燕鹰队徽，链接到接口提供的个人主页，只有作者名时进入相关 GitCode 仓库。头像缺失或加载失败回退队徽，近期动态作者也采用相同规则。资料修改后由内容推送触发 EO 重新生成。

资料对应只改变姓名、头像和入口，不按同名猜测合并统计。以下 EO 映射保留为 Git 作者别名、多邮箱合并的高级可选能力，普通成员资料对应无需填写。


GitCode贡献者接口主要返回提交作者姓名、邮箱及次数，不保证返回平台账号和头像。因此支持三种对应键：

| 键 | 对应内容 | 规则 |
| --- | --- | --- |
| `login:example-user` | GitCode账号 | 不区分大小写；常用于动态作者 |
| `author:Example Author` | Git提交作者姓名 | 精确匹配，区分大小写；不等于平台账号 |
| `email:example@example.test` | Git提交作者邮箱 | 不区分大小写，仅在函数内匹配，不发送到网页 |

一个人有多个Git作者名、邮箱或GitCode账号时，放到同一个 `accounts` 数组。例如：

```json
[
  {
    "name": "成员甲",
    "accounts": [
      "login:example-user",
      "author:Example Author",
      "email:example@example.test"
    ]
  },
  {
    "name": "成员乙",
    "accounts": ["author:Another Author"]
  }
]
```

- `name`填写网站成员档案中的姓名，匹配后复用其头像和个人介绍入口；只有已建档案的人才生成站内个人页链接。
- 同一个人所有身份可以跨所配置的仓库合并提交数。未配置映射时，同一邮箱可合并；不同邮箱的同名作者不合并，无邮箱的同名作者跨仓库也不自动合并。
- 一个身份不能同时对应两个人；同条上游记录的邮箱、作者名和账号若对应不同人，该项会显示读取失败，不猜测归属、不将错误伪装成空榜。
- 姓名、头像与个人介绍入口从同一份成员档案取得；未匹配成员统一使用圆形燕鹰队徽，图片失效也回退队徽。接口提供已知账号时进入GitCode个人页，只有作者名时进入相关仓库，不编造个人主页。
- 原始邮箱、GitCode令牌及上游原始响应不发送到网页，人员映射只保存在函数运行时配置。

## 统计与更新范围

1. 贡献榜按 `type=authors` 读取GitCode提交作者的 `contributions`，汇总全部纳入仓库，显示前8名。GitCode该接口返回的作者列表完整参与汇总，不沿用GitHub单页100人的限制；这是所选仓库接口返回范围内的提交次数，不等于代码质量、工时或团队全部历史贡献，也不是本周新增提交数。
2. 最近更新采用每个仓库最近20条动态，合并后按时间显示最近20条；普通页面每次5条，大屏每次2条，每20秒换组。未知类型、被标记敏感或日期无效的事件不展示，不把作者私有原始数据或动态JSON直接铺到页面上。
3. 当前支持推送、合并、打开/关闭/重新打开事项、评论、创建内容和发布版本等已识别动作。动态点击进入对应仓库，不根据缺失字段编造PR或提交地址。
4. 各仓库的贡献榜与动态分别缓存：有令牌10分钟、无令牌30分钟。飞书任务仍每30秒更新，网页每次轮询不会强制重新拉取GitCode。
5. 单项失败不清空其它正常项，显示仓库更新中断；失败后至少60秒再尝试，最多保留一天内的上次结果及其真实更新时间。超时不会阻断飞书任务或其它仓库。
6. 缓存仅存在当前函数实例内，实例重启后重新读取。组织、排除项、仓库、令牌、人员映射或看板凭证变更后使用独立作用域，不复用旧配置结果；迁移EO时复制上述配置即可，代码活动仍由GitCode保存。

## 脱敏联调诊断

访问口令验证成功后的接口响应中，`development.organization.authenticated`仅说明函数有无读取到令牌配置，不证明令牌有效。目录失败的`reason`、仓库的`contributionsReason`/`eventsReason`只返回HTTP状态（如HTTP_403）、固定格式错误码或READ_FAILED，不返回密钥、上游错误正文或任意异常文本。页面仍显示原有业务提示；联调应先区分配置未生效、接口认证/访问策略、限流、超时和格式错误，再决定修复方向，不能直接扩为全读写。

## 启用后的核对

- 提供实际仓库链接，再判断是否需要令牌；公开仓库可先尝试匿名读取，不能假设所有接口都允许匿名访问。
- 确认看板出现目标仓库及同步状态，对照GitCode核对作者次数、最新动态和人员对应关系。
- 对一名有网站档案的队员核对头像和个人页链接；检查同一项目没有同时配置多份镜像。
- 撤销或更换令牌后重新部署，确认提示符合实际情况；不要用模拟预览的截图作为生产接通证据。
