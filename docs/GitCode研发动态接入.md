# GitCode 研发动态接入

任务看板的“研发动态”只接入 GitCode，包含代码贡献榜、最近更新及各仓库同步状态。飞书继续提供任务，两部分独立读取；无需新增数据库，也不需要修改飞书表格。

## 配置仓库

在 EO 项目中为函数运行时设置以下变量，保存后按 EO 要求重新部署。以下仓库和账号均为占位示例，不是已接通的团队仓库。

| 变量 | 用途 |
| --- | --- |
| `DASHBOARD_GITCODE_REPOS` | 必填才能显示研发动态；最多5个仓库，英文逗号分隔 |
| `DASHBOARD_GITCODE_TOKEN` | 接口需要认证时填写有读取权限的个人访问令牌，仅放在EO函数运行时 |
| `DASHBOARD_GITCODE_PEOPLE` | 可选，JSON数组，将提交作者或账号对应到队员姓名 |

仓库可以填写简写或完整地址，也兼容末尾的 `.git` 和 `/`：

```text
example-team/robot,https://gitcode.com/example-team/documents
```

仅接受 `gitcode.com` 下的仓库，不接受组织首页、Issue页面、其它平台、带令牌参数或账号密码的地址。重复填写同一仓库只统计一次；同一项目存在不同镜像或Fork时，应只配置作为统计依据的那一份，不会跨仓库自动判断提交是否相同。

没有设置仓库时整块隐藏，不自动扫描组织、账号下的所有仓库。配置错误时显示“仓库配置待检查”，飞书任务继续正常展示。原来的 `DASHBOARD_GITHUB_REPOS` 与 `DASHBOARD_GITHUB_TOKEN` 不再读取，可从EO删除；仅保留旧页面响应字段兼容，不再访问GitHub接口。

GitCode令牌由管理员直接填写到EO，不发到聊天、不提交仓库、不使用 `NUXT_PUBLIC_` 前缀。函数只请求所配置仓库的贡献者和动态，不读取源码、不执行写入。令牌能够读取的私有仓库，其作者统计和动态会展示给能够访问当前看板的人，应按实际看板受众选择仓库和令牌权限。

## 对应人员、头像及个人页

GitCode贡献者接口主要返回提交作者姓名、邮箱及次数，不保证返回平台账号和头像。因此支持三种对应键：

| 键 | 对应内容 | 规则 |
| --- | --- | --- |
| `login:example-user` | GitCode账号 | 不区分大小写；常用于动态作者 |
| `author:Example Author` | Git提交作者姓名 | 精确匹配，区分大小写；不等于平台账号 |
| `email:example@example.test` | Git提交作者邮箱 | 不区分大小写，仅在函数内匹配，不发送到网页 |

一个人有多个Git作者名、邮箱或GitCode账号时，放到同一个 `accounts` 数组。例如：

```json
[
  {
    "name": "成员甲",
    "accounts": [
      "login:example-user",
      "author:Example Author",
      "email:example@example.test"
    ]
  },
  {
    "name": "成员乙",
    "accounts": ["author:Another Author"]
  }
]
```

- `name`填写网站成员档案中的姓名，匹配后复用其头像和个人介绍入口；只有已建档案的人才生成站内个人页链接。
- 同一个人所有身份可以跨所配置的仓库合并提交数。未配置映射时，同一邮箱可合并；不同邮箱的同名作者不合并，无邮箱的同名作者跨仓库也不自动合并。
- 一个身份不能同时对应两个人；同条上游记录的邮箱、作者名和账号若对应不同人，该项会显示读取失败，不猜测归属、不将错误伪装成空榜。
- 有平台头像则使用平台头像，否则使用已有成员头像；图片失效或仍无头像时显示姓名首字。没有本站档案但上游提供有效账号时可以进入GitCode个人页，只有作者姓名时不凭空拼接账号链接。
- 原始邮箱、GitCode令牌及上游原始响应不发送到网页，人员映射只保存在函数运行时配置。

## 统计与更新范围

1. 贡献榜按 `type=authors` 读取GitCode提交作者的 `contributions`，汇总已配置仓库，显示前8名。GitCode该接口返回的作者列表完整参与汇总，不沿用GitHub单页100人的限制；这是所选仓库接口返回范围内的提交次数，不等于代码质量、工时或团队全部历史贡献，也不是本周新增提交数。
2. 最近更新采用每个仓库最近20条动态，合并后按时间显示最近20条；普通页面每次5条，大屏每次2条，每20秒换组。未知类型、被标记敏感或日期无效的事件不展示，不把作者私有原始数据或动态JSON直接铺到页面上。
3. 当前支持推送、合并、创建/关闭/重新打开事项、评论、创建内容和发布版本等已识别动作。动态点击进入对应仓库，不根据缺失字段编造PR或提交地址。
4. 各仓库的贡献榜与动态分别缓存：有令牌10分钟、无令牌30分钟。飞书任务仍每30秒更新，网页每次轮询不会强制重新拉取GitCode。
5. 单项失败不清空其它正常项，显示仓库更新中断；失败后至少60秒再尝试，最多保留一天内的上次结果及其真实更新时间。超时不会阻断飞书任务或其它仓库。
6. 缓存仅存在当前函数实例内，实例重启后重新读取。仓库、令牌、人员映射或看板凭证变更后使用独立作用域，不复用旧配置结果；迁移EO时复制上述配置即可，代码活动仍由GitCode保存。

## 启用后的核对

- 提供实际仓库链接，再判断是否需要令牌；公开仓库可先尝试匿名读取，不能假设所有接口都允许匿名访问。
- 确认看板出现目标仓库及同步状态，对照GitCode核对作者次数、最新动态和人员对应关系。
- 对一名有网站档案的队员核对头像和个人页链接；检查同一项目没有同时配置多份镜像。
- 撤销或更换令牌后重新部署，确认提示符合实际情况；不要用模拟预览的截图作为生产接通证据。
