# 赛事倒计时配置

配置文件：网站仓库 `app/data/competitions.ts`。只修改该文件即可维护赛事；展示顺序与数组顺序一致。

当前按用户指定的队内最终形态目标倒计时：

| 节点 | 目标时间（北京时间） | 状态 |
| --- | --- | --- |
| 2027RMUL最终形态 | 2027-01-04 00:00:00 | 最终形态目标 |
| 2027RMUC最终形态 | 2027-03-08 00:00:00 | 最终形态目标 |

采用 `dateStatus: 'target'`，移除旧的参考年份，不再使用2026赛事首场的同期推算日期。这里维护的是队内最终形态目标；页面按秒倒计时，到点显示“已到达节点”。

## 修改方式

| 字段 | 填写方式 |
| --- | --- |
| `name` | 页面显示的赛事名称，可改为具体分区赛、国赛或其它节点 |
| `startsAt` | 日期待定时为 `null`；已有日期时使用 `YYYY-MM-DDTHH:mm:ss+08:00`，年月日与时分秒均填两位数字，年份四位；明确采用北京时间 |
| `dateStatus` | `pending`：待定；`historical`：去年同期参考；`tentative`：暂定；`confirmed`：已确认；`target`：队内最终形态目标 |
| `referenceYear` | 仅`historical`填写目标年份的上一赛季年份（当前为2026），其它状态移除此字段 |
| `enabled` | `true` 展示，`false` 隐藏 |

1. 未定日期：同时设置 `startsAt: null`、`dateStatus: 'pending'`。
2. 队内最终形态目标使用 `target`，不填写 `referenceYear`；得到暂定或确认的赛程后，填写实际时间，并将 `dateStatus` 同时改为 `tentative` 或 `confirmed`，同时移除`referenceYear`。请明确该节点采用报到时间还是比赛开始时间，可通过赛事名称说明。
3. 需要更多节点时复制一项并修改名称；名称不可重复。所有项均隐藏时，整个赛事栏不显示。
4. 运行 `npm run competitions:test`，完成常规静态构建检查，提交并推送 `main`，由现有 EO Git 集成部署后生效。

倒计时位于顶部标题两侧，手机在标题下并排展示，两框等宽等高、内部镜像，天数靠近中央标题。它独立于任务搜索和组别筛选，按北京时间展示目标时间，按秒更新；到达节点后显示“已到达节点”，不会出现负数。暂定日期明确标注“暂定”；往届推算显示参考年份、同期推算及“距离参考日期”，防止误认为官方赛程。

每张卡片的名称旁等比显示 RoboMaster 官方蓝色标志，图片源位于内容仓库 `public/images/competitions/robomaster.png`。保留官方原图，深色看板使用浅色小底板；图片不依赖外部链接，不改变目标日期和状态标注。

桌面大屏根据加入赛事栏后的剩余空间重新计算任务分页容量；手机仍完整展示当前筛选任务并向下滚动。

这是静态站配置：修改后需要重新部署，刷新飞书任务不会更新赛事配置。配置随网站源码保存，不需要新增飞书表格、EO 环境变量或数据库。

构建时会检查状态、日期存在性、时区和重复名称。填写错误会中止构建，并指出 `app/data/competitions.ts` 中对应赛事；不会将错误日期作为正式倒计时上线。
