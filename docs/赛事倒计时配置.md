# 赛事倒计时配置

配置文件：网站仓库 `app/data/competitions.ts`。只修改该文件即可维护赛事；展示顺序与数组顺序一致。

当前按用户要求参考2026赛季，将比赛首场时间推算到2027年同月同日：

| 赛事 | 2027同期推算目标（北京时间） | 参考依据 |
| --- | --- | --- |
| RMUL 山东站 | 2027-03-20 15:00 | 2026山东站3V3小组赛首场，手册第19页 |
| RMUC 东部赛区（济南） | 2027-05-21 08:30 | 2026东部赛区小组赛首场，手册第18页 |

页面均标注“去年同期参考（2026）”及“同期推算”，这些目标不是2027官方赛程。“去年”指目标2027赛季的上一赛季2026，不是当前日历年份的去年。日期包括小时分钟都沿用参考节点；不是预测实际开赛时间。

依据来自官方[2026 RMUL手册目录](https://bbs.robomaster.com/wiki/20204847/809872)中的《山东站参赛手册V2.0》（2026-03-04），及[2026 RMUC手册目录](https://bbs.robomaster.com/wiki/20204847/809871?source=7)中的《东部赛区参赛手册V2.0.0》（2026-04-30）。官方汇总公告包含报到日，本配置采用手册内首场比赛时间，未使用3月19日、5月18日报到日期。

## 修改方式

| 字段 | 填写方式 |
| --- | --- |
| `name` | 页面显示的赛事名称，可改为具体分区赛、国赛或其它节点 |
| `startsAt` | 日期待定时为 `null`；已有日期时使用 `YYYY-MM-DDTHH:mm:ss+08:00`，年月日与时分秒均填两位数字，年份四位；明确采用北京时间 |
| `dateStatus` | `pending`：待定；`historical`：去年同期参考；`tentative`：暂定；`confirmed`：已确认 |
| `referenceYear` | 仅`historical`填写目标年份的上一赛季年份（当前为2026），其它状态移除此字段 |
| `enabled` | `true` 展示，`false` 隐藏 |

1. 未定日期：同时设置 `startsAt: null`、`dateStatus: 'pending'`。
2. 得到暂定或确认的赛程后，填写实际时间，并将 `dateStatus` 同时改为 `tentative` 或 `confirmed`，同时移除`referenceYear`。请明确该节点采用报到时间还是比赛开始时间，可通过赛事名称说明。
3. 需要更多节点时复制一项并修改名称；名称不可重复。所有项均隐藏时，整个赛事栏不显示。
4. 运行 `npm run competitions:test`，完成常规静态构建检查，提交并推送 `main`，由现有 EO Git 集成部署后生效。

赛事栏位于解锁后的看板任务概览与任务列表之间。它独立于任务搜索和组别筛选，按北京时间展示目标时间，按秒更新；到达节点后显示“已到达节点”，不会出现负数。暂定日期明确标注“暂定”；往届推算显示参考年份、同期推算及“距离参考日期”，防止误认为官方赛程。

每张卡片的名称旁等比显示 RoboMaster 官方蓝色标志，图片源位于内容仓库 `public/images/competitions/robomaster.png`。保留官方原图，深色看板使用浅色小底板；图片不依赖外部链接，不改变参考日期和状态标注。

桌面大屏根据加入赛事栏后的剩余空间重新计算任务分页容量；手机仍完整展示当前筛选任务并向下滚动。

这是静态站配置：修改后需要重新部署，刷新飞书任务不会更新赛事配置。配置随网站源码保存，不需要新增飞书表格、EO 环境变量或数据库。

构建时会检查状态、日期存在性、时区和重复名称。填写错误会中止构建，并指出 `app/data/competitions.ts` 中对应赛事；不会将错误日期作为正式倒计时上线。
